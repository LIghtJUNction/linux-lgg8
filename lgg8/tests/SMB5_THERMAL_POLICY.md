# SMB5 纯温控策略核心（离线，未接充电）

`drivers/power/supply/qcom_smb5_thermal_policy.c/.h` 是一个无 I/O 的状态转换函数。
没有 regmap、时钟读取、分配、workqueue、设备访问，也没有 Kconfig/Makefile 接线。
当前 SMB5 观察驱动不调用它。测试通过不表示可充电或硬件已停充。

## 重复测试

从仓库根目录运行：

```sh
python -B lgg8/tests/test_smb5_thermal_policy.py
python -B lgg8/tests/test_smb5_thermal_policy.py --cc clang --strict-only
python -B -m unittest discover -s lgg8/tests -p test_smb5_thermal_policy.py -v
```

依赖 Linux `memfd_create`、Python 3、C 编译器和 `/usr/bin/ld`。
默认执行严格 C11 和 UBSan 两种构建；UBSan 运行需要编译器能找到 `libubsan.so`。
每种构建由独立子进程运行，避免动态加载器复用相同 fd 路径的旧库。
完整核心和 C 测试各编译为匿名 memfd 对象，再链接到匿名共享库并执行。
不使用 `/tmp`、临时目录、内核构建、手机或网络，不留下构建产物。
`-B` 阻止生成 Python 字节码；测试前后比较核心、头文件和 C 测试的 SHA-256。

测试直接调用完整 C 接口，不重写策略，不按源码文字判断正确性。
枚举温度范围的用例检查停充与电池上限等不变量；独立表格检查具体阈值和电流。
另外覆盖错误、年龄边界、未来/倒退时间戳、会话重用、重连及极大整数。
测试中的校准范围、1000 ms 年龄和电池限值全部是合成夹具。

## 接口与状态约定

调用 `qcom_smb5_thermal_policy_step(config, state, input)`，取得建议和 `result.next`。
初次把 `state` 置零或传 NULL。调用方串行处理，并在包括错误/停充在内的每次返回后
保存 `next`。函数不修改输入。不要在错误、拔线或重新插线时清空历史状态。

输入包含连接状态、会话号、会话开始时间、当前时间，以及一份共同采集的温度/电压样本。
样本分别有温度有效位、电压有效位、错误码、采集时间和所属会话。
任何非零错误（正数也包括在内）或任一有效位缺失均停充；`-1` 温度是 -0.1 °C，
不是错误哨兵。传感器返回 25 °C 不自动代表有效，调用方必须提供真实采集的有效性。

时间使用同一来源的、包括系统休眠时间的单调毫秒时钟。年龄由当前时间减采集时间计算，
不得用调用函数的时间刷新旧采样时间。`age >= max_sample_age_ms` 即过期。
有效旧样本可在期限内重复评估，超时必须再次调用本函数才能产生停充建议；本核心没有计时器。
硬件中的采样更新时间与“主机刚读到 SRAM”不是一回事，调用方必须证明样本新鲜度。

每次 attach 使用非零、严格递增的会话号；不得回绕或复用。样本必须来自该会话，
采集时间不得早于 attach。调用方不能给旧缓存换标签来伪造新样本。
如果调用方漏报断连、重新初始化状态、伪造时间/有效位，本核心无法重建真实事件。

没有单独断连输入而直接替换活动会话号时，新开始时间也不得早于上一会话最后一次
可信连接观察 `last_connected_at_ms`。该下界使用本次更新之前的观察；等于下界允许
同一毫秒内有序更换会话。连接身份和时钟通过校验后即更新观察，与配置/采样是否
成功无关；错误会话及倒退时钟不更新它。`last_now_ms` 则继续记录非倒退调用的时间，
用于检测后续时钟回退。两者分开，避免错误请求推进时钟水位后，正确的会话重试
被错误地拒绝。失败后仍须保存 `next`，重试仍受断连下界、样本新鲜度和滞回检查。

断连始终给停充建议，并撤销会话有效状态；即使断连事件的时钟倒退也撤销该状态。
有效断连观察会记录 `session_start_floor_ms`；后续新会话的开始时间必须大于或等于
此下界，样本又必须不早于会话开始，因此不能用断连前的数据授权。重复观察到断连时，
下界随有效单调时间向前推进；等于下界允许同一毫秒中的有序断连/重连。
断连时间倒退时返回 `CLOCK_REGRESSED`，保留 `last_now_ms`，并用最后可信的时间提升
撤销下界，绝不采信倒退时间或降低原下界。这仍是失败/停充结果；只有后续非倒退时间、
新会话及合格新样本通过全部检查才可能恢复温控建议。
重新连接需要新会话和本次连接的新样本。
温区滞回历史独立于会话保留：HOT 后重新插线时 53 °C 仍为 HOT，必须低于 52 °C；
COLD 后重新插线时 2 °C 仍为 COLD，必须达到 3 °C。
错误和过期也保留原温区，避免恢复读取时绕过滞回。

会话回归反例：会话 1 开始于 100、采样于 200，1000 时断连；1001 时即便会话号
递增为 2，声称开始于 900、采样于 950，也返回 `BAD_SESSION` 和停充建议。
测试还覆盖下界前一毫秒、等于/晚于下界、回填旧样本、重复断连、倒退时钟，以及
`UINT64_MAX` 时间边界。原测试在旧核心上因缺少停充建议而失败。

活动会话替换反例：会话 1 开始于 100、在 200 观察到连接和样本；201 时声称
会话 2 开始于 150、样本来自 190，现返回 `BAD_SESSION`。保存失败后的 `next`，
202 时把会话 2 的开始/样本时间修正为 200，可以恢复温控建议。测试覆盖下界
前一毫秒/相等/后一毫秒、错误请求后的纠正重试、替换前后的时钟倒退、配置/采样
错误仍记录连接观察、HOT/COLD 滞回，以及零和 `UINT64_MAX` 边界。

此次新增 28 项回归检查：修复前，原核心在活动会话替换反例上因没有给出停充建议
而触发断言失败；修复后，严格 C11 与 UBSan 各通过 25,392 项，现有 unittest
包装入口也通过。所有构建仍只使用匿名 memfd，Python 运行器保持原样。

输出 `stop_charging=true` 时，FCC/FV 均为零：这是明确停充建议，零不是“释放限制”，
也不是要求写 FV=0。`stop_charging=false` 仅表示通过这一层温控判断，不能授权硬件充电。
输出电流是电池侧 FCC（µA），电压为电池 FV 上限（µV），都不是 USB/PD 输入合同。
其他保护/协议/总功率限制须继续取更严格者。

## 固定版本参考及有意改变的行为

来源均固定到 LG/LineageOS
`d4f335e13d73c4aa2af85581a6ec11b670ee5b94`：

- [温区状态机与电压分支](https://github.com/LineageOS/android_kernel_lge_sm8150/blob/d4f335e13d73c4aa2af85581a6ec11b670ee5b94/drivers/power/supply/lge/protection-battemp.c#L189-L403)。
- [公共 BTP 参数](https://github.com/LineageOS/android_kernel_lge_sm8150/blob/d4f335e13d73c4aa2af85581a6ec11b670ee5b94/arch/arm64/boot/dts/lge/sm8150_common/sm8150_common-pm.dtsi#L120-L149)。
- [alpha 的最低容量 3400 mAh](https://github.com/LineageOS/android_kernel_lge_sm8150/blob/d4f335e13d73c4aa2af85581a6ec11b670ee5b94/arch/arm64/boot/dts/lge/sm8150-alpha/sm8150-alpha_common/sm8150-alpha_common-pm.dtsi#L229-L234)。

温度单位为 0.1 °C。冷恢复 3 °C；COOL 在低于 10 °C 进入、达到 12 °C 恢复；
WARM 在 45 °C 进入、低于 43 °C 恢复；HOT 在 55 °C 进入、低于 52 °C 恢复。
首次 UNKNOWN 按当前温度选择温区。CHILLY 额外限制包含 0～15 °C 两端点。

| 温区 | FCC 建议 | FV 建议 |
|---|---|---|
| COLD/HOT | 停充 | 不提供写入建议 |
| COOL，电池 <4 V | 最低容量的 30%，向下取整至 50 mA，再受电池 FCC 上限约束 | 电池 FV 上限 |
| COOL，电池 ≥4 V | 至多 500 mA | 电池 FV 上限 |
| GOOD | 电池 FCC 上限 | 电池 FV 上限 |
| WARM | 最低容量的 50%，向下取整至 50 mA，再受电池 FCC 上限约束 | 至多 4.0 V |
| CHILLY 叠加 | 电池 <4 V 时 50%；否则至多 1000 mA；与已有限制取更小值 | 不额外改变 |

区别于下游：读取错误/过期/断连始终停充；不返回 RELEASED 哨兵，不采用启动假温度，
不释放停充票来重触发充电。停充期间不建议修改 FV，即使下游 HOT 会请求 4 V。
下游 VFLOAT 执行器中的 OCV 检查、临时停充、投票以及寄存器写入均未移植；
本函数返回 4 V 建议不表示可在当前电池电压下直接降低硬件 FV。

## 真实设备证据仍缺失

不存在默认允许的配置；全零配置或缺少必要参数都停充。调用方必须显式给出：

| 参数/前提 | 需要的证据 |
|---|---|
| `max_sample_age_ms` | 真实传感器更新周期、采集耗时、通知/调度延迟和休眠唤醒保障；1000 ms 只用于测试 |
| 温度有效性及合理范围 | 准确板型、热敏电阻/FG 编码、负温度、校准与补偿、断路/短路检测及独立测温对照 |
| 电压有效性及合理范围 | 单位、校准、实际电池端采样、采样同步与错误传播 |
| 最低容量、FCC/FV 电池上限 | 物理电池身份、选中 profile、厂家充电规范；3400 mAh/3 A/4.43 V 夹具不是验证结果 |
| 固定冷暖阈值、4 V 分界、CHILLY 和比例电流 | 对实际 LM-G820 电池和测温来源适用；下游补偿温度阈值不能自动套给主线原始温度 |
| 所有“无热限制”输出 | 仍缺输入合同、过压、终止、JEITA 硬保护、watchdog 停充、并联关闭/预算和故障执行证据 |

未来执行器必须区分“期望停充”和“已确认停充”，每次故障重试并验证读回，
不能因建议未变就跳过失败的停充。写 FCC/FV 失败不得恢复充电。
内核构建、并发调用、真实采样年龄、硬件保护配置和设备停充均未由本套测试验证。
